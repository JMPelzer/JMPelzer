## 🧭 Development & Design Philosophy

I believe good software should be **reliable, maintainable, accessible, and intuitive**.

Accessibility isn't something to add at the end of development. It's part of building quality software from the beginning.

My approach emphasizes:

- **Semantic HTML first:** Use native browser functionality before adding ARIA.
- **Keyboard accessibility:** Logical navigation, visible focus, and predictable interactions.
- **Maintainable code:** Reusable components, consistent patterns, and clear documentation.
- **Testing and debugging:** Identify problems, understand their causes, and improve solutions.
- **User-centered thinking:** Design and develop for real people with different needs.
- **Collaboration:** Learn from feedback, share knowledge, and support team development.

<details>
<summary>View my accessibility checklist</summary>

- WCAG 2.2 AA guidelines
- Text contrast of at least 4.5:1 for normal text and 3:1 for large text
- Logical tab order, skip links, and visible focus indicators
- Semantic HTML and appropriate ARIA usage
- Accessible forms with labels, instructions, and error messages
- Screen-reader and keyboard testing
- Responsive layouts and text resizing
- Respect for reduced-motion preferences
- Testing with axe, WAVE, and Lighthouse
